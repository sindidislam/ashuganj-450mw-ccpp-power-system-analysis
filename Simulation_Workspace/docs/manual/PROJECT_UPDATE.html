2. What the model represents

Ashuganj South is a single-shaft combined cycle unit: a Siemens SCC5-PAC 4000F/3000 (1S) train — one SGT5-4000F gas turbine and one SST-3000 steam turbine on a common shaft, driving one 458 MVA generator. That is why a "450 MW" plant has a single machine on the diagram rather than three.

Power leaves at 22 kV, steps up through the generator step-up transformer to the 230 kV switchyard, and exports to the PGCB grid. The unit's own auxiliaries — pumps, fans, water intake — are fed at 6.6 kV from the unit auxiliary transformer, with a station auxiliary transformer from 230 kV as the alternative supply.

3. How to run it

Everything is scripted. Nothing has to be dragged or wired by hand.

The short version

Open MATLAB, change to the matlab folder of the project, and run:

ashuganj_setup();          % puts every project folder on the path
run_load_flow_study();     % solves all four cases, writes every table

That single call builds the model from the dataset four times, solves each case, cross-checks the answers, writes the CSVs to results/load_flow/, and saves the Simulink files. It takes about a minute.

To look at the diagram

open('simulink/main/Ashuganj_South_Main.slx')

% To solve it interactively instead:
%   double-click the powergui block (top-left)
%   choose Load Flow
%   press Compute

What is deliberately not a block. Bay conductors, disconnectors, earthing switches, current and voltage transformer burdens, the generator circuit breaker and the isolated phase busbar run all appear on the plant drawing but carry no documented impedance. They are drawn as ideal connections and labelled as such. Giving them textbook impedances would put invented numbers into a study whose whole purpose is to be traceable.

6. Key code, and what each piece does

The excerpts below carry the engineering, with what each one is for. They are quoted from the source files at the moment this page is generated, with the line numbers shown, so they cannot go out of date against the code they describe. Everything else in the project is bookkeeping around these.

Where the numbers come from

Nameplates give impedance as a magnitude and a resistance percentage. The model needs reactance, split windings and a magnetising branch. That conversion happens in exactly one place, from nameplate quantities only.

data/ashuganj_transformers.mNameplate Z, R, no-load loss and excitation current → the block's parameters
Zpu = T(i).Z_pct/100;
Rpu = T(i).R_pct/100;

assert(Rpu < Zpu, ['ashuganj_transformers: %s has R >= Z, so X would be ', ...
    'imaginary. Check the nameplate transcription.'], T(i).Name);

T(i).X_pu               = sqrt(Zpu^2 - Rpu^2);
T(i).X_pct              = 100*T(i).X_pu;
T(i).X_Status           = 'DERIVED_FROM_VERIFIED_DATA';
T(i).X_Derivation       = 'X = sqrt(Z^2 - R^2) from nameplate Z and R';
T(i).R_pu               = Rpu;
T(i).Z_pu               = Zpu;
T(i).XR_ratio           = T(i).X_pu/Rpu;
T(i).XR_Status          = 'DERIVED_FROM_VERIFIED_DATA';
data/ashuganj_transformers.m, lines 352–366

The assert is not decoration: if R ever exceeded Z the square root would go imaginary and produce a complex "reactance" that Simulink would accept and quietly mis-solve. The magnetising resistance comes from no-load loss, and the magnetising inductance from excitation current with the iron-loss component removed — not from the excitation current alone, which is the common shortcut.

The grid is the one component with no nameplate. Its impedance is inferred from the switchgear's 50 kA rating, which is a rating and not a grid study — so the derivation is written out in full and the value is flagged as estimated everywhere it appears.

data/ashuganj_grid.mThe external grid equivalent, inferred from the GIS short-circuit rating
G.Ssc_MVA           = sqrt(3)*G.Vnom_V*G.Isc_kA*1000/1e6;
G.Ssc_Status        = 'DERIVED_FROM_VERIFIED_DATA';   % derived FROM AN ESTIMATE
G.Ssc_Derivation    = 'S = sqrt(3) * 230 kV * 50 kA';
G.Ssc_Note          = ['DERIVED_FROM_VERIFIED_DATA describes the ARITHMETIC ', ...
                       'only. The INPUT is ESTIMATED, so the result inherits ', ...
                       'ESTIMATED confidence. Do not quote this as verified.'];
data/ashuganj_grid.m, lines 74–79

R is set to zero exactly, not to a textbook X/R. No grid X/R is documented, and a fabricated one would look like data. The cost of that choice is stated in §9 rather than hidden.

Note UNITS'pu' first: the order matters, because the block reinterprets the numbers already in its winding fields when the unit system changes. Note also that saturation is left off — a saturation characteristic is not in the source documents, and a balanced load flow does not use one.

The two breakers are the only blocks whose state encodes the case matrix. Their switching times are pushed far into the future so that nothing ever operates: for a load flow they are static links, open or closed.

This is the part that makes the study defensible rather than merely produced: the off-nominal turns ratio and the vector-group phase shift are applied independently, the branch is solved as a T-network by hand, and the answer is compared against what the solver reported.

The YNd1 → +30°, Dyn11 → −30° mapping is the mechanism behind Finding 2, and the otherwise branch refuses to guess: an unrecognised vector group produces a warning attached to the result rather than a silent zero.

Before any of that is trusted, one sanity check on the solver's own units. If a future release ever reported bus injections in MW instead of per unit, every number in the study would be wrong by a factor of a hundred while still looking entirely plausible. The generator injection is known exactly from the case definition, so it is used as the probe.

8. What the results mean

The numbers are consistent

All four cases converge in 2 iterations, which is what a well-conditioned network of this size should do. More useful than convergence: every branch flow was rebuilt from the solved voltages and the nameplate impedances, outside the solver, and compared against the solver's own bus injections at every node.

The worst mismatch is 8.6e-08 MVA in the two radial cases and 6.1e-04 MVA in the two looped ones. The looped cases are worse for a reason worth stating: there the circulating power is the small difference between two much larger flows, so it inherits proportionally more of the solver's convergence tolerance. Even so, 6.1e-04 MVA on a 100 MVA base is below the tolerance the solve was asked to meet.

Separately, generation minus auxiliary demand minus losses equals export to 7e-13 MW — machine precision, in every case. The answers are arithmetically sound; whether they are the right answers depends on the input data, which is what §9 is about.

Finding 1 — the step-up transformer needs forced cooling at full output

At rated dispatch the step-up transformer carries 105.9 % of its 355 MVA natural-cooling rating. It is comfortable on the highest stage — 73.0 % of 515 MVA — so nothing is over-rated, but the oil pumps and fans are not optional at full load. This is a straightforward consequence of the ratings, and it is the kind of thing that is easy to miss if loading is only ever quoted against the top cooling stage.

Finding 2 — closing the station auxiliary bay makes power circulate

With the station auxiliary bay closed, the 6.6 kV board is fed from both ends at once — through the unit transformer from 22 kV, and through the station transformer from 230 kV. The two paths form a loop, and the loop carries circulating power.

The unit transformer delivers 19.90 MW into a 14.00 MW load. The surplus — 5.90 MW — leaves again through the station transformer and back into the 230 kV system. It is not consumed by anything; it simply goes round. The independent check is that the station transformer reports almost exactly that figure flowing the other way (5.90 MW), and the step-up transformer's throughput drops by the same amount.

Why it is allowed to happen at all: the vector groups permit it. Going round the loop, the step-up transformer contributes +30°, the station transformer 0° and the unit transformer −30°, which sums to zero. There is no phase barrier to stop the flow.

Why it matters: this pushes the unit auxiliary transformer to 109.6 % of its 19 MVA natural-cooling rating — over its nameplate, to supply a load well inside it. On the forced-cooling stage it is 83.3 %, so the unit is not endangered, but running both supplies in parallel is loading a transformer for no delivered power. Whether the plant actually does this is a question for the operators; the model shows what happens if it does.

Finding 3 — losses and voltages are unremarkable, which is itself the result

Losses run 0.680–0.833 MW, 0.20–0.21 % of generation. Every bus sits within 2.08 % of nominal. There is no voltage problem and no reactive problem at any of the four operating points, which is the answer the load flow was asked for — and it is the baseline the fault study will be measured against.

One caveat on the losses: they are copper and iron losses in the transformers only. The plant's cables, busbars and bay conductors have no documented impedance, so they contribute zero. The real plant loses slightly more. The figure is a floor, not an estimate.

Dispatch makes less difference than expected

Dropping from 389.30 to 342.01 MW cuts losses by 17 % but moves the 230 kV voltage by only 0.0003 pu. The grid is strong relative to the plant, so the boundary voltage barely notices the unit's output. This also means the estimated grid impedance is not doing much damage to the answers — which the sensitivity tests confirm separately.

  1. Collect the zero- and negative-sequence data listed in §9. Without it only three-phase faults can be done properly.
